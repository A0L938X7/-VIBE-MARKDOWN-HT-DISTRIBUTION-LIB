## 二、标题

### 写法

```markdown
# 一级标题
## 二级标题
### 三级标题
#### 四级标题
##### 五级标题
###### 六级标题
```

### 规则

- `#` 后必须有**至少一个空格**，否则不识别为标题。
- `##` 和 `###` 会出现在右侧「本页内容」大纲中（`####` 也会）。
- `#` 一级标题通常不建议在笔记正文中使用，因为笔记标题已由系统自动生成（来自 `learn.xml` 的 `title` 属性）。正文建议从 `##` 开始。
- 标题文字支持行内语法（粗体、代码、链接）。

### 渲染样例

```markdown
## 学习目标
```
渲染为：21px 齐伋体，字距 4px，下方有 1px 分隔线。

## 三、段落与换行

### 写法

```markdown
这是第一段文字。

这是第二段文字，与上一段之间空一行。
```

### 规则

- 段落之间用**空行**分隔。
- 段落内的单个换行会被合并为空格（Markdown 标准行为）。
- 需要强制换行时，请在行尾加**两个空格**（当前渲染器尚未支持 `<br>` 强制换行，建议改用分段）。

## 四、强调（粗体、斜体）

### 写法

```markdown
这是 **粗体文字**。
这是 *斜体文字*，会显示为朱砂色。
这是 `行内代码`。
```

### 渲染规则

| 语法 | 效果 |
|------|------|
| `**文字**` | 加粗，颜色 `var(--text)` |
| `*文字*` | 显示为朱砂色（`var(--accent)`），**不是真斜体** |
| `` `文字` `` | 等宽字体 + 软底 + 边框 |

### 注意

- `*斜体*` 与 `**粗体**` 的区别在于星号数量。渲染器会先处理 `**`，再处理 `*`。
- 斜体星号前后不能紧贴非空白字符，否则可能不识别（参考正则 `(^|[^*])\*([^*\n]+)\*(?!\*)`）。
- 如需真正的斜体样式，暂时不支持，建议改用引用块或粗体表达强调。

## 五、列表

### 无序列表

```markdown
- 第一项
- 第二项
- 第三项

* 也可以用星号
+ 或者加号
```

### 有序列表

```markdown
1. 第一项
2. 第二项
3. 第三项
```

### 规则

- 符号后必须有**至少一个空格**。
- 列表项之间**不需要空行**。
- 列表与前后段落之间需要**空行**分隔，否则可能被合并到上一段。
- **不支持嵌套列表**（多级缩进）。如需层级，可用标题或分段代替。
- **不支持任务列表** `- [ ]`，会原样显示为文本。

## 六、引用块与 Callout（重点）

### 普通引用块

```markdown
> 这是一段引用文字。
> 可以跨多行。
```

渲染为：左侧 3px 灰边框 + 软底 + 三级文字色。

### Callout（朱砂提示框）—— 本系统特色

**语法**：引用块第一行是 `**标题**` 形式，则渲染为朱砂提示框。

```markdown
> **术语纠正**
> 东北篇原书杂神门表格中所谓「六神」列……
> 这是第二行内容。
```

**渲染结果**：

```
┌──────────────────────────────────┐
│ 术语纠正                          │  ← 朱砂色加粗
│ 东北篇原书杂神门表格中所谓……       │  ← 正常文字
│ 这是第二行内容。                   │
└──────────────────────────────────┘
   背景：朱砂浅底，左边 3px 朱砂
```

### 规则

- 第一行必须是 `> **xxx**` 形式（星号内不能含换行）。
- 从第二行开始的所有引用行都作为 callout 正文。
- callout 标题建议简短（4-8 字），常用如「学习提示」「重要」「注意」「术语纠正」。

### 常用 Callout 示例

```markdown
> **学习提示**
> 初学者不要同时混用两派牌名与起卦方向。

> **重要**
> 东北响马卦不看生克只是便捷玩法。

> **注意**
> 太极、两仪不考虑生克。

> **术语纠正**
> 六神只有六个：青龙、白虎、朱雀、玄武、腾蛇、勾陈。
```

## 七、分隔线

### 写法

```markdown
---
```

也可以：

```markdown
***
___
```

### 规则

- 三个或以上的 `-`、`*`、`_` 独占一行，且允许中间有空格。
- 渲染为 1px 水平细线。

## 八、表格（GFM 风格）

### 写法

```markdown
| 宫位 | 牌名 | 吉凶 |
|------|------|------|
| 乾 | 八万 | 吉 |
| 坤 | 二条 | 凶 |
| 艮 | 一并 | 凶 |
```

### 规则

- 第一行是表头，第二行是分隔行（必须是 `|---|` 形式，可以有冒号表示对齐，但当前渲染器不解析对齐）。
- 数据行从第三行开始。
- 每行的列数**建议与表头一致**；不足时会用空字符串补齐。
- 单元格内容支持行内语法（粗体、代码、链接）。

### 渲染效果

- 表头背景 `var(--bg-panel)`
- 所有单元格 1px 边框
- 表头 `white-space: nowrap`，不换行

### 注意

- 表格前后必须有**空行**。
- 表格行内**不能用 `|` 作为内容**（会被当作列分隔符）。如需表示，请用「或」代替。

## 九、链接与图片

### 链接

```markdown
[响马卦官方站点](https://example.com)
```

渲染为蓝色可点击链接，新窗口打开。

### 图片

```markdown
![姜玄衣头像](../img/jiang.jpg)
```

渲染为自适应宽度的 `<img>`，最大宽度 100%。

### 规则

- 图片路径建议用相对路径（相对 md 文件所在目录）。
- 支持 PNG / JPG / SVG / GIF / WebP。
- 如果图片加载失败，浏览器会显示 alt 文字。

## 十、代码

### 行内代码

```markdown
使用 `fetch()` 加载 md 文件。
```

渲染为：等宽字体 + 软底 + 边框。

### 代码块

````markdown
```js
function hello() {
  console.log('Hello');
}
```
````

### 规则

- 三个反引号包围，可指定语言（当前渲染器不解析语言，仅作为整体代码块）。
- 代码块内的所有字符**不解析 Markdown 语法**。
- 代码块内容会被 HTML 转义，`<` `>` `&` 等安全显示。
- 代码块前后必须有**空行**。

### 注意

- 代码块内的三个反引号不能嵌套（如需显示，请用四个反引号包围）。
- 当前渲染器不支持代码高亮。

## 十一、HTML 与转义

### 转义

Markdown 中的以下字符会被转义为 HTML 实体：

| 字符 | 显示 |
|------|------|
| `<` | `&lt;` |
| `>` | `&gt;` |
| `&` | `&amp;` |
| `"` | `&quot;` |
| `'` | `&#39;` |

### 直接写 HTML

**不支持**。所有 HTML 标签会被转义为文本显示。如果需要在笔记中展示 HTML，请放在代码块里。

### 特殊字符

- **竖线 `|`**：在表格行中有特殊含义。普通段落中可正常使用。
- **星号 `*`**：用于粗体和斜体。如需显示字面星号，请用 `` `*` `` 包起来。
- **反引号 `` ` ``**：用于代码。如需显示字面反引号，请用两个反引号包围，如 ``` `` ` `` ```。

## 十三、不支持或有限支持的语法

### 明确不支持

- **嵌套列表**：多级缩进会被拉平为一级列表。
- **任务列表** `- [ ]` / `- [x]`：会原样显示为文本。
- **脚注** `[^1]`：会原样显示。
- **定义列表**：无对应语法。
- **数学公式** `$...$` / `$$...$$`：会原样显示。
- **HTML 内嵌**：所有标签被转义为文本。
- **自动链接** `<https://example.com>`：会原样显示。
- **删除线** `~~文字~~`：会原样显示。
- **高亮** `==文字==`：会原样显示。

### 有限支持

- **表格对齐**：`|:---|` / `|---:|` 语法被识别但不对齐。
- **代码语言**：` ```js ` 的语言标识被忽略，仅作为代码块。
- **强制换行**：行尾两个空格会被吞掉，建议用分段或 `<br>` 替代。
- **图片尺寸**：不支持 `![alt](src =100x200)` 语法。

### 如需扩展

编辑 `js/learn.js` 的 `mdToHtml` 函数。该函数是纯字符串处理，无外部依赖，扩展时：

1. 找到对应语法的处理分支（如 `inline()` 处理行内，主循环处理块级）。
2. 增加新的正则匹配与 HTML 输出。
3. 测试新语法不影响已有语法。

## 十四、写作规范建议

### 命名规范

- 笔记标题使用简洁、明确的名词短语，如「九宫象法」「碰牌十法」。
- 避免使用特殊字符（`#`、`?`、`%`、空格）作为文件名。

### 结构规范

- 每篇笔记建议从 `##` 二级标题开始，`#` 一级标题留给系统自动生成。
- `##` 用于章节，`###` 用于小节，`####` 用于更细的划分。
- `##` 与 `###` 会出现在右侧「本页内容」大纲中，建议每篇笔记至少有两个 `##`。

### Callout 使用建议

- 每篇笔记 0-3 个 callout，不宜过多。
- 优先使用「学习提示」「重要」「注意」「术语纠正」这四类。
- 标题 4-8 字，正文 1-3 行。

### 表格使用建议

- 每篇笔记 0-3 个表格，用于对照、分类、参数说明。
- 表格列数建议 3-6 列，超过 6 列会横向拥挤。
- 表头短（2-4 字），单元格内容简短。

### 与其他笔记的关联

- 在 `learn.xml` 的 `related` 属性中声明关联笔记 id，用于知识图谱。
- 在 md 正文中可以用 `[文字](learn.html?note=ne-1)` 形式链接到其他笔记。
